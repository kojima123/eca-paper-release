# エージェントはいつ考えずに行動できるか
### ARC-AGI-3 の LLM エージェントにおける実行契約と停止記録による診断

## 問題
LLM エージェントは、一度解けた課題を、次回は推論し直さずに実行できる能力として保持し、その能力が通用しなくなったときに推論へ戻れるか。私たちの対照エージェント（Daniel Franzen の Milestone 2 ハーネス上の Qwen3.8 Flash-Next）は、成功を実行できる形で残さない。同じ設定が公開 8 ゲームで 2 回の実行に 31 と 38 レベルをクリアした。83 回の実行で一度でもクリアしたレベルは 45 あるが、1 回あたりでは 33.3 にとどまる。同じ設定の 4 回では、12 レベルが回によってクリアできたりできなかったりした。内蔵のソルバーを切ると、ソルバーなら生成トークンなしで打てる 13 レベルに、モデルは 1 回あたり 36〜51 万トークンを使う。一度解いても、次が安くならない。

成功を保存するだけでも足りない。保存した手順が現在の状態に合うとは限らない。盤面の見た目が同じでもゲームの内部状態が違うことがあり、実行が予測から外れることもある。だから保存した手順には、使い始めてよい条件、使い続けてよい条件、止めて引き継ぐ条件が要る。熟練した人間はこの役割分担の例になる。自転車に乗れる人はペダルのこぎ方を考えず、予想外のことが起きたときに考え直す（Logan 1988; Schmidt 1975; Norman & Shallice 1986）。

評価は 2 つの場面に分ける。既知の公開ゲームでは、成功が技能になるかと再利用の費用を、未見のゲームでは、技能がどこまで適用できるかを測る。

## 手法：1 つの実行契約
私たちはこの層 ECA（Existential-Cognition Architecture）を、制御の 1 歩ごとに基盤モデルに問い合わせられないフィジカル AI のミドルウェアとして作り始めた。ARC-AGI-3 では、ECA はハーネスとゲームの間に入るミドルウェア全体を指し、ゲート、技能の出どころ、補助的な構成要素を含む。**技能**は、観測が予測どおりである間だけ LLM なしで手を打ち（何を照合するかは技能源ごとに定める）、最初に外れた時点で、位置と理由を添えて制御を返す。技能は 2 種類ある。

- **型（mechanic family）**：公開ゲームを基に事前実装した 15 のパラメータつきモデル。そのレベルでそれまでに観測した遷移をすべて予測できるときだけ認証され、先頭部分実行器が権限の下でその計画を打つ。型は提出したカーネルのソルバーだった。本稿では契約を測るための固定の技能源として使い、モデルの獲得方法としては提案せず、汎化も主張しない。
- **事例の再生**：エージェント自身の実行から回収し、再生で検証した過去の成功。開始盤面のハッシュで照合し、毎手ハッシュで確かめる。

LLM は監督者で、新しいことと、技能が外れた後に手を打つ。その成功は、実行と実行の間に新しい技能にまとめられる。提出したカーネル（ECAOD v1）は、Franzen のノートブックに、この契約の下で必要時だけ動く型のツールボックスを加えたものである。評価は 36.14、32.60、23.67 で、元のノートブックそのままは 29.69 と 27.58 だった。ばらつきが約 12 点あるので、非公開評価での改善は主張しない。失敗ノート版（30.68）は、どの型がどこで破れ、何を予測していたかも LLM に伝える。

## 結果（事前登録、公開 8 ゲーム、1 ゲーム 60 分）
- **成功から技能へ。** LLM は s5i5 L7 を一度、65 手、19 ターン、22.5 万トークンでクリアした。回収して 61 手に短縮すると、続く 2 回の実行でトークン 0 で再生された。
- **一度出会ったものの再生。** 再生は 182 回中 182 回一致し、LLM トークンは 0 だった。実行あたりのレベル数は 34.5 から 45〜46 に、ゲームスコアの平均は 42.8 から 66.5〜67.7 に上がり、トークンは 182 万から 134〜138 万に減った。カーネルには 2 つのハーネス修正も入っているので、これはシステム同士の比較である。
- **権限か助言か。** 同じ認証済みの計画を、1 行の助言として LLM に渡した。モデルは 73〜86% 従い、同じ 13 のソルバーレベルをクリアしたが、そのすべてで LLM のターンが必要になり、1 回あたり 76〜85 ターン、23.5〜25.2 万トークン、71〜90 ゲーム分を使った。ソルバーが権限を持つ場合は、52 回中 45 回を LLM のターンなしで打ち、各ゲームで最後にクリアした担当レベルまでで、4 回を通して 4〜34 ターン、0.5〜14 万トークン、10〜39 分だった。この範囲には、認証できず LLM もクリアできなかった 1 レベルを含めていない。それを含めると、その実行の担当レベルは 30.9 万トークンとなり、助言条件のどちらの実行よりも多かった。節約が成り立つのは技能が適用された範囲で、システム全体についてではない。助言は次の 1 手を示す約 45 トークンの 1 行なので、費用はプロンプトの長さではなく LLM のターン数で決まる。
- **逸脱の後の引き継ぎ。** 仕込んだ逸脱では、16 回中 16 回、仕込んだ位置で再生が止まった。再生が到達した盤面（即時の停止が守る先行分）から引き継いだ LLM は 16 レベル中 11 をクリアし、最初から解かせた場合は 16 中 7 だった。引き継ぎからの手数は中央値で 41 と 117 だった。主な要因は引き継ぎのノートではなく、この先行分と考えられる。この n では差は有意でない（Fisher、p = 0.29）。
- **LLM は技能を自分で書けるか。** 同じ契約の下で、LLM がレベルの遷移関数と目標をコードで書き、ハーネスが検証・計画・実行した（自前の 198 手で 5 レベル）。91 回の探索のうち 49 回は、記録と矛盾しないモデルの下で「届かない」と結論し、20 の計画のうち 13 は新しい領域の最初の手で止まった。レベル数は 69 から 55 に下がった。各検査をその時点で有効だったモデルの版に対応づけて、停止のそれぞれをその後まで追った（事前登録した再解析）。13 件の停止は 5 つのレベル試行の中で起き、そのすべての後に新しい版が定義された。5 試行中 3 試行で記録済みの全遷移と一致する版に到達し、同じ 1 実行の dc22 の 2 レベルではハーネスがクリアした。手数は LLM 単独と同程度だった（40 対 38/37、72 対 82/72）。記録には停止の後にハーネスがクリアした例があるが、対照を上回る性能は示しておらず、モデルの不十分さと検証・探索の費用の影響も切り分けていない。
- **初見。** 未見の 33 ゲーム（NVIDIA の 25、別の作者の 8）では、型が認証されたのは 2 回で、どちらも最初の 1 手で取り消され、技能は 1 レベルも生まなかった。非公開評価の成績に対する構成要素ごとの寄与は切り分けていない。

## なぜ止まったか
契約の下では、止まるたびに、観測したこと、考えられる原因、それを切り分ける測定を記録する。170,714 遷移のうち、くり返された（ゲーム、盤面、手）のキーの 19.8% が違う次の盤面につながり、キーにレベルを入れても変わらなかった。つまり、レベルの中で盤面だけでは状態を表しきれていない。6 手までの履歴でそのキーの 63% を区別でき、別の実行では、答える場合（40%）に 83.7% 正しかった（盤面だけの多数決は 74.4%）。レベルが変わるところでは、前のレベルに当てはめた効果テンプレートの予測器（LLM なし）が、次のレベルの遷移を正確に予測できたのは 1,240 遷移の 10.3% で、1,112 件の失敗のうち 445 件は表現できない効果だった。目標がもう 1 つの隙間で、完了判定が成り立ったのはクリア 114 回中 0 だった。

## 意味
対照のエージェントは解を見つけられるが、それを技能として保持しない。**経験はリセットされ、記憶を読む。** 重みは固定で、実行をまたいで実行できる形で残るものがなく、コンテキストは約 20 リクエストごとに空にされる。検証された技能は第 3 の記憶である。残り、正確で、生成トークンなしで実行されるが、まだ一般化しない。自分の成功を、一般化する技能に変えることが、残る課題である。今回の実行では、確認済みの技能は適用できた範囲で生成トークンなしに実行された。認証できなければ費用は LLM に戻り、LLM が書いたモデルは、レベルの見ていない部分を予測するよりも、記録と一致することの方が多かった。

*Daniel Franzen の Milestone 2 のノートブックと Tufa Labs の Duck ハーネスを土台にした。実験、解析コード、執筆は AI コーディングエージェント（Anthropic の Claude Code）の支援を受けて行った。研究の方向、判断、主張は著者のものである。*
